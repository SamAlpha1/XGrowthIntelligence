# Security Policy

Project owner and maintainer: **SamAlpha1**  
X: **@samalpha_**

## Scope

Security reports should focus on credential exposure, accidental X write capability, unsafe workflow permissions, public leakage of user-specific analytics, dependency issues, or bypasses of the read-only boundary.

## Reporting

Do not publish bearer tokens, credentials, private analytics, or exploit details in a public issue. Contact the maintainer through the project owner's public GitHub or X profile before disclosing sensitive details.

## Supported boundary

Version 1 is read-only toward X. Any capability that creates, changes, or deletes X-side content or relationships is outside the supported security boundary.
